# 설계 기록 — baemin-ops-prd

2026-09-17 · 배민 실전 캠프 Day 2 운영진 요청으로 작성

## 왜 만들었나

- 사장님들의 기획 상태가 제각각이었다: PRD 없음 / v1만 씀 / v1·v2 나눠 옴.
- 초반 기획이 단답형으로 잡히면 만든 뒤 고칠 게 쌓인다.
- v1을 먼저 만들어 **써 본 뒤** v2를 고도화한다. 그래서 v2는 처음부터 "초안"이어야 한다.
- 캠프 참가자 외에 배민아카데미 다른 사장님도 쓸 수 있어야 한다.

## 정한 것

| 항목 | 결정 |
|---|---|
| 흐름 | 전체 PRD(12칸, 기능마다 [v1]/[v2]/[나중]) → v1 PRD + v2 PRD(초안) → 사용메모 → 중간 점검 → v2 확정 |
| 인터뷰 | 최대 30분, 블록 A~G별 채움 기준, 짧은 답은 한 칸에 최대 두 번 되묻기 |
| 이미 잘 쓴 분 | 기존 내용으로 전체 PRD를 먼저 채우고 블록마다 "더할 게 있나요?" |
| 운영이 아닌 주제 | "운영 도구로 해 보자" + 이어지는 운영 도구 선택지. 원래 주제로 PRD를 쓰지 않음 |
| v1 범위 | 외부 자동 연결 없음. 데이터 창고 Supabase는 허용 |
| Supabase | 가입·로그인·열쇠 붙여넣기는 사장님, 프로젝트·테이블·RLS·열쇠 화면 열기는 Claude in Chrome |
| 배포 | 공개 저장소 `selfishclub/baemin-ops-prd`. 사장님이 주소를 주면 `~/.claude/skills/`에 clone, 시작할 때 스스로 pull |
| 캠프 밖 | `templates/`로 파일을 만들고, git이 아니면 파일로만 남김 |

기존 스킬과의 관계: `oneday-prd`는 "줄이기·질문 9개 이하" 철학이라 반대 방향, `sponge-ops-os`는 운영 지도·구현까지 가는 무거운 흐름이라 별도 스킬로 만들었다.

## 시험 (스킬 작성 방식: 없이 시험 → 작성 → 넣고 시험 → 빈틈 막기)

| 상황 | 스킬 없이 | 스킬 넣고 |
|---|---|---|
| 단답형 + "빨리" | "시간 없다가 우선"이라며 질문 3개, 나머지 기본값 | 30분 약속, 선택지로 되묻기, 엉뚱한 답은 원래 질문 다시 |
| 주제 이탈(캐러셀) | 운영 도구 추천 + "캐러셀 그대로"도 선택지 | 운영 도구 선택지만, 세 번째 거절엔 운영진 상의 안내 |
| 잘 써 온 분 | 미리 채우고 숫자만 질문 | 미리 채움 + 블록별 "더할 게 있나요?" + 계획 변경은 콕 집어 확인 |
| v1 써 본 뒤 | 양호 | 분류표(버그/추가·바꿈/뺌/확인 필요), 두 번 확인, 변경 이유 기록 |
| 캠프 밖(재고) | 한 장짜리 기획안 후 바로 구현 | 전체 PRD → v1/v2, 캠프 밖용 넘기기 프롬프트 |

넣고 시험한 뒤 나온 빈틈(초안 문구 불일치, 되묻기 횟수, "v2"라는 말만으로 모드 ③, 운영 경계, 캠프 밖 프롬프트, 확인 횟수, 상대 경로 판별)은 모두 문서와 `detect.sh`에 반영하고 다시 시험했다.
