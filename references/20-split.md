# 20 · v1 / v2 나누기

`PRD_전체.md` 4번 기능 표에 꼬리표를 붙이는 기준. 기능마다 "그렇게 나눈 이유"를 한 줄 쓴다.

## 기준

| 꼬리표 | 기준 |
|---|---|
| **[v1]** | (모두 맞아야 함) 오늘(하루) 바이브 코딩으로 가능 · 다른 서비스에서 자동으로 가져오거나 보내는 연결 없음 (**데이터 창고 Supabase는 v1에서도 쓴다**) · 핵심 흐름 **한 바퀴가 처음부터 끝까지** 돈다 · 폰에서 열린다 |
| **[v2]** | 써 본 뒤 한 달 안에 가능하면서, 다음 중 하나: 자동 연결(배민 데이터, 날씨 API, 카톡·문자 알림 등) · 권한 나누기(직원 로그인 등) · 여러 매장 · 자동 불러오기 |
| **[나중]** | 다음 중 하나: 결제·송금 · 승인·심사가 오래 걸림 · 비용이 큼 · 아직 필요가 불분명 |

운영이 아닌 원래 주제(캐러셀 등)는 4번 표에 넣지 않고 11번에 "나중에 따로"로만 적는다.

## 순서

1. 핵심 흐름을 한 줄로 쓴다: "(누가) (무엇을 넣으면) → (무엇이 나오고) → (남는다)".
2. 그 흐름에 꼭 필요한 기능만 [v1]. 3~5개가 적당하다. 6개를 넘으면 가장 늦게 쓰이는 것부터 [v2]로.
3. 나머지는 [v2] 또는 [나중].
4. 사장님께 표로 보여 주고 확인받는다. 옮기는 걸 "자르는 게 아니라 v2로 옮기는 것"이라고 말한다.

## 옮겨 쓰기

- `v1/PRD.md` (8칸 양식): 1~4는 전체 PRD에서 요약, 5번은 [v1] 기능 + "이번에 하지 않을 것"(= [v2]·[나중] 목록), 6번은 시연 입력·기대 결과(전체 9번) · 잘못 입력했을 때(전체 7번) · 다시 열었을 때(전체 6번), 7번은 [v2] 요약, 8번은 전체 8번 그대로.
- `v2/PRD.md`: 제목 줄 바로 아래에 초안 표시. 5번 안에 `**꼭 할 것**` / `**여유 있으면**` 소제목을 만들어 [v2] 기능을 나눈다(꼭 할 것은 1~2개). 준비물(API 키 발급, 채널 심사 등)도 5번에 적는다.
- 이미 있는 `v1/PRD.md`(모드 ②)는 덮어쓰지 않고 다른 줄만 맞춘다.
- 전체 PRD 12번에 "(날짜) 처음 작성 · v1/v2 나눔"을 적는다. (모드 ③에서 v1 PRD로 미리 채운 경우는 "(날짜) v1 PRD에서 옮겨 처음 작성" 한 줄)

## v2 초안 표시 (제목 바로 아래, 한 줄)

| 때 | 문구 |
|---|---|
| 모드 ①② (아직 안 써 봄) | `> 초안 — v1을 써 본 뒤 고칩니다` |
| 모드 ③, 중간 점검 전 | `> 초안 — 중간 점검에서 확정` |
| 모드 ③, 점검 뒤 또는 사장님이 확정이라고 함 | 표시를 지운다 |

캠프의 중간 점검 날짜는 10/2이고, **10/2 당일 점검이 끝나기 전까지는 "점검 전"**이다. 캠프 밖이면 모드 ③을 시작할 때 점검 계획이 있는지 묻고, 없으면 사장님이 "확정"이라고 할 때까지 `> 초안 — v1을 더 써 보고 확정`을 쓴다.

## "꼭 할 것"이 넘칠 때

후보가 셋 이상이면 순서대로 고른다: ① 사용메모의 **손으로 한 일**을 가장 많이 줄이는 것 ② 준비 기간이 짧은 것(심사·승인 없음) ③ 나머지는 "여유 있으면" 또는 [나중].

## 흔한 실수

| 실수 | 고치기 |
|---|---|
| v1에 카톡 알림·배민 연동을 넣음 | 외부 연결이라 [v2]. v1은 "복사 버튼"이나 "화면에 표시"로 대신한다 |
| v1이 입력 화면만 있고 결과가 안 나옴 | 한 바퀴가 돌아야 한다. 결과 화면·저장까지 넣는다 |
| v2 "꼭 할 것"이 셋 이상 | 꼭 할 것 1~2개. 나머지는 "여유 있으면"(한 달 안에 될 때) 또는 [나중] |
| 나눈 이유가 비어 있음 | 한 줄이라도 쓴다. 모드 ③에서 이 이유를 다시 본다 |
